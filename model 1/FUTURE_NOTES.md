# Future Notes

- **Auto-tune the renderer** — close the human-in-the-loop gap with a VLM (diagnoses synth-vs-real differences) + coding agent (edits `render_synthetic.py`) + discriminator metric (stop when classifier acc → ~60%). If convergence is tight, may eliminate the need for the CycleGAN entirely.
- **CycleGAN root-cause cleanup** — current run used an early checkpoint (e020-e030) because later epochs had black-bar artifacts and content fade (D dominated, D-loss → 0.03). Proper fix is a re-render (no edge clipping; pull char anchors inward / cap rotated-char width) + a shorter retrain with lower D LR, λ_cycle=20+, ~30-40 epochs total, and early-stop when D-loss falls below ~0.3.
- **VGG-perceptual cycle loss** — replace/augment the L1 cycle loss with a frozen-VGG feature distance so character edges/curves are anchored harder than raw pixels. Use only if higher λ_cycle alone still lets chars degrade. Risk: occasional checkerboard texture; tune the weight low.
- **Diversity #1 — PARSeq training augmentation** — biggest leverage against overfitting. Add albumentations transforms each batch: random color jitter, gaussian blur, random erasing, JPEG compression, mild rotation/perspective. Effectively unlimited unique samples per epoch. ~30 lines in `src/parseq/train.py` dataset.
- **Diversity #2 — wider renderer manifold** — expand `render_synthetic.py`: pull ~30 more readable Windows fonts into pool, add multi-layer chromatic shadow (1 or 2 echoes), more background variants (gradient, watermark blobs, radial fade), wavy per-char baseline, alternating tilt patterns, per-char stroke-width nudge. Makes synth distribution broader so PARSeq generalizes further.
- **Diversity #3 — multi-modal CycleGAN (MUNIT)** — stochastic G_AB conditioned on a noise vector so one synth maps to many real-style outputs. Low marginal gain here because the renderer already covers the 3 observed real-data styles; only worth doing if we hit a hard accuracy ceiling.

- **Case-folded PARSeq + CNN-only case decision** — split responsibility cleanly: train PARSeq on the case-folded charset (36 classes: 10 digits + 26 letters), retire all case decisions to the char-CNN's 3-class case head. Why: (1) PARSeq's output head gets 1.7× more capacity per class; (2) visually-symmetric letter pairs (Cc, Oo, Pp, Ss, Vv, Ww, Xx, Zz, Kk, Mm, Uu, Yy) merge into single classes — the dominant source of PARSeq's per-position error disappears by construction; (3) PARSeq cannot make case errors at all, so the autoregressive decoder bias on case is gone; (4) cleaner ensemble math — no α weighting, just "PARSeq says letter, CNN says case, apply." Cost: ~25 min retrain + ~15 min code/eval. Risk: full delegation to CNN — if CNN's per-position case acc on real data is bad, this regresses. Currently char-CNN val_case is 95.5% on synth (epoch 7, still climbing), so the floor looks acceptable. Decide based on ensemble eval result first: if Strategy G (case-flip override) gives >2 pt lift over baseline, the CNN signal is good enough on real and this proposal becomes the cleaner replacement.

## Recent-paper ideas (research scan, May 2026)

- **PARSeq decoder-only pretraining** ([DPTR, 2024](https://arxiv.org/html/2408.05706v1)) — pretrain the autoregressive decoder on text strings alone (no images), then load weights into full PARSeq and fine-tune. Strong gains for natural-language scene text; *limited* expected gain on uniform-random alphanumeric captchas (no language structure to learn beyond uniform priors). Worth trying as a 2-3h experiment if main accuracy plateaus.
- **Diffusion-based synthetic captcha generation** ([Diff-CAPTCHA, 2023](https://arxiv.org/abs/2308.08367) + 2025 style-transfer follow-ups) — replace PIL renderer with a fine-tuned diffusion model conditioned on text strings. Generates captchas with deep fusion of chars and backgrounds — much higher fidelity than PIL. Bigger lift; potentially eliminates synth-vs-real gap entirely.
- **Self-training / pseudo-labeling** — once we have a decent PARSeq, run inference on the 651 (or new unlabeled real) captchas, take top-K confidence predictions as pseudo-labels, retrain. Bursztein-style attacks reach 51-100% on 33 schemes with this loop. Cheap (~1h) and doesn't violate "no human labels" mandate. Best follow-up after we have a baseline real-eval number.
- **Test-time augmentation (TTA)** — at inference, run cleaner with 3-5 different threshold configurations + run PARSeq on each + majority-vote final answer. ~15 lines of code, typically 2-5pt accuracy bump.
- **TPS rectification** (Thin-Plate-Spline) — standard preprocessing in scene-text recognition that "un-warps" distorted characters before recognition. Could help with heavily-rotated CryptBB chars. Medium effort; prepend a STN-style module to PARSeq.
- **VLM benchmark validation** ([Open CaptchaWorld, NeurIPS 2025](https://arxiv.org/html/2505.24878v1)) — best VLMs (OpenAI-o3, GPT-4.1) hit only 21-40% on captcha benchmarks; humans 93%. Confirms specialised solvers like PARSeq still beat general foundation models — our chosen path is the right one.
- **PARSeq itself** ([Bautista & Atienza, ECCV 2022](https://arxiv.org/abs/2207.06966)) — paper context: 91.9% with synth training, 96% with real training on standard STR benchmarks. Our 87% synth-val is in the right zone; the gap to real-data accuracy is a distribution-shift problem, not a model-quality problem.
