# auto_synth — label-free captcha replication

## What this project is

Given a folder of unlabeled captcha images from any target system, build a
synthetic generator that replicates that system's captchas. **No human
labels from the dataset are used.** Pretrained generic models (DINOv2, SAM,
etc.) may be used for image understanding; ground-truth labels are not.

The deliverable is a per-scheme pipeline: `unlabeled_images/ → synth_generator`.
Train a recogniser on the generator's output, evaluate on a held-out labeled
set of the same scheme. Success = recogniser trained on this synth performs
comparably to one trained on hand-tuned synth.

## Why this exists

Existing synth pipelines (`E:/pranav/model 1/` for CryptBB, `synthetic image
generation/` for DarkBay) all required some human-in-the-loop component:
- CryptBB pipeline: ported MyBB's `captcha.php` line-by-line — required reading
  the source captcha library
- DarkBay parametric renderer: hardcoded `CHARSET="..."`, hardcoded image
  geometry, hand-tuned distortion knobs

For schemes whose source isn't available and whose alphabet is unknown, neither
approach scales. This project addresses that.

## The three components

The user's framing: split the problem into three orthogonal sub-tasks that can
each be solved without labels, then ensemble.

### Part A — Alphabet discovery

**Input**: folder of unlabeled captcha images.
**Output**: the character set that appears in this scheme.

The model must figure out *which characters exist* in this scheme without
being told. Same captcha may be used many times. The model just needs the
character bank, not per-image labels.

### Part B — Font / glyph style

**Input**: alphabet from Part A + same unlabeled images.
**Output**: a callable `render_glyph(char, style_seed) → glyph_image` that
produces a glyph in the target scheme's style for any character in the
alphabet.

The model must learn *what each character looks like* in this scheme.
Same captcha may be used many times. The model just needs to learn the font.

### Part C — Noise / background

**Input**: same unlabeled images (and optionally character masks from Parts A/B).
**Output**: a callable `sample_background() → bg_image` that produces a
realistic noise/background image for this scheme.

The model must learn *what the noise looks like*. Same captcha may be used
many times. The model just needs the background pattern.

### Ensemble

```
def render_synthetic_captcha(text, alphabet, font_model, bg_model):
    bg = bg_model.sample()
    for char in text:
        glyph = font_model.render(char, sample_style())
        bg = compose(bg, glyph, position=layout())
    return (bg, text)            # synth captcha + label
```

The label is generated by the renderer itself — no human in the loop.

## Constraints

- **No labels from the target dataset's eval set.** Pretrained generic models
  (SAM, DINOv2, generic OCR) are allowed as "tools" but not the dataset's
  own labels.
- **One scheme = one config + a folder of unlabeled real images.** No new code
  per scheme.
- **Validation requires a held-out labeled eval set** to measure recogniser
  accuracy; that labeled set is never seen during synth-generator training.

## Validation criteria

For each target scheme:
1. **Generator trains a working recogniser** — PARSeq trained on auto_synth
   output achieves competitive accuracy on the held-out labeled eval set.
2. **Generality** — same code runs on a second scheme by changing only a
   config + unlabeled-images folder.
3. **Comparable to hand-tuned baselines** — auto_synth's recogniser reaches
   within X% of the equivalent hand-tuned-synth recogniser. (X TBD per scheme.)

## Datasets in scope

(All in `E:/pranav/`.)

| Scheme | Unlabeled count | Labeled (eval-only) | Native size | Notes |
|---|---|---|---|---|
| Courier Market | 2510 | none yet | ~200×60 | Best starting candidate — most data, no baseline obligation |
| City | 2000 | none yet | 324×81 | Different aspect, tests generality |
| CryptBB | 600 (`model 1/data/raw/`) | 651 (`model 1/data/eval/`) | 200×60 | Has Model 2.5 baseline (57.60% w / 89.04% c) — head-to-head benchmark |
| DarkBay | — (eval-contamination) | 1000 | 200×50 | Skip until unlabeled source resolved |
| JoeyRetitling | 651 | — | varies | Untouched so far |

**First target: Courier Market.** Most data, no baseline obligation, clean test.
**Second target: CryptBB.** Has a hand-tuned baseline to beat or tie.

## Out of scope

- Real-time deployment / API
- Beating the hand-tuned CryptBB baseline (Model 2.5 at 57.60% w) on absolute
  terms — auto_synth is *expected* to underperform a hand-tuned pipeline by
  some margin; the test is whether the gap is small enough to be worth the
  generality.
